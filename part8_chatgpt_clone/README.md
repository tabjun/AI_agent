## 1. 비동기(Async/Await) 호출의 판단 기준

### 왜 어떤 코드에는 `await`를 붙이고, 어떤 곳엔 `asyncio.run()`을 쓰는가?
그 차이는 **"누가 이 함수를 호출하느냐"**와 **"함수의 정의가 어떠한가"**에 달려 있다.

*   **판단 근거 (함수 시그니처):** 함수가 `async def`로 선언되어 있다면, 이 함수는 호출 즉시 결과를 주는 것이 아니라 "나중에 실행될 약속(코루틴)"을 반환한다. 이 약속을 실행해서 결과값을 꺼내려면 반드시 `await` 키워드가 필요하다.
*   **비동기 환경 여부:**
    *   **비동기 함수 내부:** 다른 비동기 함수를 호출할 때는 `await`를 직접 사용할 수 있다. (예: `await session.get_items()`)
    *   **동기 환경 (Streamlit 메인 루프):** Streamlit의 일반적인 스크립트 실행 환경은 동기(Sync) 방식이다. 동기 환경에서는 `await`를 직접 쓸 수 없으므로, **`asyncio.run()`**이라는 도구를 사용하여 비동기 함수를 강제로 실행시켜야 한다.
*   **주의할 점:** `asyncio.run(await ...)`와 같이 중복으로 사용하는 것은 문법적 오류이다. `asyncio.run()` 안에는 실행할 코루틴(함수 호출 형태)만 전달해야 한다.

## 2. Streamlit 채팅 레이아웃: "상자(Container) 안에 상자" 개념

채팅 구현 시 `run_agent()`의 위치를 선정하는 것은 레이아웃의 성패를 결정한다. 이를 이해하기 위해 **"상자(Box) 비유"**를 활용한다.

### 📦 직관적인 비유: 상자 개념
Streamlit에서 `with st.chat_message('human'):` 코드는 화면에 **'사용자용 전용 상자'**를 하나 만드는 것과 같다. 이 `with` 문 안에 들어가는 모든 내용(`st.write` 등)은 그 상자 안에 차곡차곡 쌓이게 된다.

### ❌ 문제 상황: 상자 안에 상자 넣기 (Nesting Error)
```python
if prompt:
    with st.chat_message('human'):
        st.write(prompt)
        # ⚠️ 사용자 상자가 아직 열려있는 상태에서...
        asyncio.run(run_agent(prompt)) # 이 함수 내부에서 'AI용 상자'를 또 만들려고 함!
```
*   **문제의 핵심:** `run_agent()` 함수 내부에는 `with st.chat_message('ai'):` 코드가 들어있다. 위와 같이 작성하면 **사용자 상자 안에 AI 상자를 집어넣으려는 시도**가 된다.
*   **결과:** Streamlit은 디자인 규칙상 **채팅 상자 안에 또 다른 채팅 상자를 넣는 중첩(Nesting)을 허용하지 않는다.** 이로 인해 레이아웃이 깨지거나 출력이 비정상적으로 발생한다.

### ✅ 해결책: 독립적인 상자 배치
사용자가 질문을 입력했을 때만 실행되어야 하므로 `if prompt:` 안에는 있어야 하지만, 상자가 겹치면 안 되기 때문에 사용자 상자(`with`)는 완전히 닫은 후 AI 상자를 열어야 한다.

```python
if prompt: # 1. [실행 조건] 사용자가 입력을 했을 때만 실행해라!
    
    with st.chat_message('human'): # 2. [사용자 상자 열기]
        st.write(prompt)           # 3. 사용자가 쓴 글을 상자 안에 넣는다.
    # 4. <여기서 사용자 상자가 완전히 닫힘 - 들여쓰기 끝>

    asyncio.run(run_agent(prompt)) # 5. [AI 상자 생성] 이제 독립적으로 AI 상자를 만들어 답변을 써라!
```

## 3. 핵심 요약 및 복습 포인트

1.  **`if prompt:` 안에 넣는 이유:** 사용자가 아무런 입력을 하지 않았는데 AI가 먼저 답변을 생성하는 불필요한 실행을 막기 위해서이다. (실행 조건의 제어)
2.  **`with` 블록 밖에 넣는 이유:** 사용자 말풍선 안에 AI 말풍선이 들어가는 "레이아웃 인셉션" 상황을 방지하고, 대등한 위치에 메시지를 쌓기 위해서이다. (레이아웃의 독립성)
3.  **개발 시 팁:** Streamlit에서 `with`는 시각적인 경계를 만드는 작업이다. 내가 지금 만드는 UI 요소가 다른 요소의 **내부**에 들어가야 하는지, 아니면 **다음**에 와야 하는지를 들여쓰기(Indentation)를 통해 명확히 구분해야 한다.

# 2026.4.21 공부: 데이터 구조 안정성 및 비동기 초기화

오늘의 학습은 OpenAI Assistants API의 복잡한 데이터 구조를 안전하게 처리하는 방법과 Streamlit의 실행 생명주기 내에서 비동기 함수를 초기화하는 이유를 다룬다.

### 1) `st.write` 대신 `st.markdown`을 사용하는 이유
*   **명시적 렌더링:** `st.write`는 입력 타입에 따라 출력을 자동으로 결정하는 범용 함수다. 반면, 챗봇 응답은 **코드 블록, 굵은 글씨, 리스트** 등 마크다운 형식이 핵심이다.
*   **일관성:** `st.markdown`을 사용하면 Streamlit이 해당 텍스트를 마크다운으로 해석하도록 강제하므로, 텍스트의 형식이 깨지지 않고 의도한 대로 렌더링됨을 보장할 수 있다.

### 2) 복잡한 `isinstance` 및 `len()` 체크가 필요한 이유
OpenAI의 최신 SDK(특히 Assistants API)는 메시지 내용을 단순 문자열이 아닌 **리스트 형태**로 반환하는 경우가 많다.
*   **구조 대응:** `content=[{ "type": "text", "text": { "value": "..." } }]`와 같은 구조에서 실제 텍스트만 뽑아내기 위해 `isinstance(message['content'], list)` 체크가 필요하다.
*   **방어적 프로그래밍:** `len(message['content']) > 0` 체크는 리스트가 비어있을 때 `[0]` 인덱스에 접근하여 발생하는 **`IndexError`를 방지**하는 최소한의 안전장치다. 
*   **앱 안정성:** Streamlit은 코드 한 줄에서 에러가 나면 전체 앱 화면이 멈춘다. 유저에게 JSON 객체를 그대로 노출하지 않고, 어떤 상황에서도 앱이 죽지 않게 하기 위해 다소 보수적인 타입 체크를 수행하는 것이 실무적인 정석이다.

### 3) `asyncio.run(display_chat_history())`의 역할
*   **상태 복원 (Load History):** 이 코드는 앱이 새로고침(Rerun)될 때마다 데이터베이스(SQLite)에 저장된 이전 대화 내용을 읽어와 화면에 다시 그려주는 역할을 한다.
*   **동기-비동기 브릿지:** `display_chat_history`는 DB 조회를 위해 `async def`로 정의된 비동기 함수다. 하지만 Streamlit의 메인 실행 흐름은 동기 방식이므로, 앱이 시작될 때 이 비동기 작업을 완료하기 위해 `asyncio.run()`으로 감싸서 호출해야 한다.
*   **실행 위치의 중요성:** 채팅 입력창(`st.chat_input`)보다 위에서 실행되어야 이전에 나눴던 대화들이 먼저 화면에 출력되고, 그 아래에 새로운 입력창이 나타나 자연스러운 채팅 흐름을 유지할 수 있다.

# 2026.4.22 학습 내용: Hosted Tools 활용 및 비동기 흐름 이해

### 1. 핵심 개념: Hosted Tools (내장 도구)
기존의 `function calling`은 개발자가 직접 함수를 정의하고 실행 로직을 작성해야 했습니다. 반면, **OpenAI Agent SDK의 Hosted Tools**는 OpenAI 인프라에서 직접 실행되는 도구(예: `WebSearchTool`)를 모델에 간단히 연결만 하면 바로 사용 가능한 방식입니다.

### 2. 'role' Key Error가 발생하는 이유 및 해결
`WebSearchTool`을 사용하면 세션(DB)에 사용자/AI 메시지 외에 도구 호출(`tool_calls`) 및 결과 데이터가 섞여 들어옵니다. 이 데이터들은 `role` 키가 없기 때문에, UI 출력 시 `if 'role' in message:`와 같은 방어적 코드가 반드시 필요합니다.

추가로 로컬 개발 환경을 넘어 가상화된 컨테이너 환경(Docker)을 구축하고, 외부에서도 내 서비스를 안전하게 테스트할 수 있는 터널링 기술을 다룬다.

### 1) Docker Volume과 Auto-Rerun의 관계
*   **문제점:** 기본 Docker 빌드는 파일을 이미지 안으로 '복사'하므로, 호스트에서 코드를 수정해도 컨테이너 안에는 반영되지 않는다.
*   **해결책 (Volumes):** `docker-compose.yml`에서 `volumes: - .:/app` 설정을 통해 프로젝트 폴더와 컨테이너 내부를 실시간으로 연결한다.
*   **Streamlit 환경 변수:** `STREAMLIT_SERVER_RUN_ON_SAVE=true`를 설정하여 코드가 저장될 때마다 Streamlit이 이를 감지하고 자동으로 화면을 새로고침하게 만든다.

### 2) 멀티모달(Vision) 데이터 처리 (Image Upload)
*   **Base64 인코딩:** `file_uploader`로 받은 이미지 파일을 LLM이 인식할 수 있는 텍스트 형태(Base64)로 변환하여 전달한다.
*   **Content List 구조:** OpenAI Agents SDK는 텍스트와 이미지를 동시에 보낼 때 `[{"type": "text", ...}, {"type": "image_url", ...}]` 형태의 멀티모달 리스트 구조를 요구한다.

### 3) Cloudflare Tunnel을 이용한 무료 외부 노출
*   **ngrok과의 차이:** `ngrok` 무료 버전은 인증 및 유효 기간 제약이 있으나, `cloudflared`는 로그인 없이도 안정적인 무료 터널링을 제공한다.
*   **실행 명령어:** `cloudflared tunnel --url http://localhost:8000` 한 줄로 전 세계 어디서든 접속 가능한 보안 터널을 생성할 수 있다.

## 1. 비동기(Async/Await) 호출의 판단 기준

### 왜 어떤 코드에는 `await`를 붙이고, 어떤 곳엔 `asyncio.run()`을 쓰는가?
그 차이는 **"누가 이 함수를 호출하느냐"**와 **"함수의 정의가 어떠한가"**에 달려 있다.

*   **판단 근거 (함수 시그니처):** 함수가 `async def`로 선언되어 있다면, 이 함수는 호출 즉시 결과를 주는 것이 아니라 "나중에 실행될 약속(코루틴)"을 반환한다. 이 약속을 실행해서 결과값을 꺼내려면 반드시 `await` 키워드가 필요하다.
*   **비동기 환경 여부:**
    *   **비동기 함수 내부:** 다른 비동기 함수를 호출할 때는 `await`를 직접 사용할 수 있다. (예: `await session.get_items()`)
    *   **동기 환경 (Streamlit 메인 루프):** Streamlit의 일반적인 스크립트 실행 환경은 동기(Sync) 방식이다. 동기 환경에서는 `await`를 직접 쓸 수 없으므로, **`asyncio.run()`**이라는 도구를 사용하여 비동기 함수를 강제로 실행시켜야 한다.
*   **주의할 점:** `asyncio.run(await ...)`와 같이 중복으로 사용하는 것은 문법적 오류이다. `asyncio.run()` 안에는 실행할 코루틴(함수 호출 형태)만 전달해야 한다.

## 2. Streamlit 채팅 레이아웃: "상자(Container) 안에 상자" 개념

채팅 구현 시 `run_agent()`의 위치를 선정하는 것은 레이아웃의 성패를 결정한다. 이를 이해하기 위해 **"상자(Box) 비유"**를 활용한다.

### 📦 직관적인 비유: 상자 개념
Streamlit에서 `with st.chat_message('human'):` 코드는 화면에 **'사용자용 전용 상자'**를 하나 만드는 것과 같다. 이 `with` 문 안에 들어가는 모든 내용(`st.write` 등)은 그 상자 안에 차곡차곡 쌓이게 된다.

### ❌ 문제 상황: 상자 안에 상자 넣기 (Nesting Error)
```python
if prompt:
    with st.chat_message('human'):
        st.write(prompt)
        # ⚠️ 사용자 상자가 아직 열려있는 상태에서...
        asyncio.run(run_agent(prompt)) # 이 함수 내부에서 'AI용 상자'를 또 만들려고 함!
```
*   **문제의 핵심:** `run_agent()` 함수 내부에는 `with st.chat_message('ai'):` 코드가 들어있다. 위와 같이 작성하면 **사용자 상자 안에 AI 상자를 집어넣으려는 시도**가 된다.
*   **결과:** Streamlit은 디자인 규칙상 **채팅 상자 안에 또 다른 채팅 상자를 넣는 중첩(Nesting)을 허용하지 않는다.** 이로 인해 레이아웃이 깨지거나 출력이 비정상적으로 발생한다.

### ✅ 해결책: 독립적인 상자 배치
사용자가 질문을 입력했을 때만 실행되어야 하므로 `if prompt:` 안에는 있어야 하지만, 상자가 겹치면 안 되기 때문에 사용자 상자(`with`)는 완전히 닫은 후 AI 상자를 열어야 한다.

```python
if prompt: # 1. [실행 조건] 사용자가 입력을 했을 때만 실행해라!
    
    with st.chat_message('human'): # 2. [사용자 상자 열기]
        st.write(prompt)           # 3. 사용자가 쓴 글을 상자 안에 넣는다.
    # 4. <여기서 사용자 상자가 완전히 닫힘 - 들여쓰기 끝>

    asyncio.run(run_agent(prompt)) # 5. [AI 상자 생성] 이제 독립적으로 AI 상자를 만들어 답변을 써라!
```

## 3. 핵심 요약 및 복습 포인트

1.  **`if prompt:` 안에 넣는 이유:** 사용자가 아무런 입력을 하지 않았는데 AI가 먼저 답변을 생성하는 불필요한 실행을 막기 위해서이다. (실행 조건의 제어)
2.  **`with` 블록 밖에 넣는 이유:** 사용자 말풍선 안에 AI 말풍선이 들어가는 "레이아웃 인셉션" 상황을 방지하고, 대등한 위치에 메시지를 쌓기 위해서이다. (레이아웃의 독립성)
3.  **개발 시 팁:** Streamlit에서 `with`는 시각적인 경계를 만드는 작업이다. 내가 지금 만드는 UI 요소가 다른 요소의 **내부**에 들어가야 하는지, 아니면 **다음**에 와야 하는지를 들여쓰기(Indentation)를 통해 명확히 구분해야 한다.
